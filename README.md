# Ленинблок

Сайт продуктов Леонида Макарова для `https://leninblock.ru`. Репозиторий: [leninblok/leninblock-site](https://github.com/leninblok/leninblock-site). Next.js App Router, TypeScript, обычный CSS. Без CMS, базы данных, аналитики и секретов.

## Маршруты

| Путь | Содержимое |
| --- | --- |
| `/` | Автор и ссылки на два продукта |
| `/kruzhok` | Интерактивный кружок с видео, камера и скачивание |
| `/bible` | Знакомство с игрой, кнопка перехода на её отдельный сайт |
| `/play` | HTTP 307 на `https://www.wherefrombible.ru/` |
| `/sitemap.xml`, `/robots.txt` | Индексация трёх страниц |

Неизвестные адреса, включая `/easm` и `/work`, возвращают 404. `www.leninblock.ru` перенаправляется на основной домен с HTTP 308; это правило сработает после подключения обоих доменов к хостингу.

## Локальная работа

Node.js 20.9+ (для нового хостинга используйте поддерживаемую LTS-версию, например Node.js 24).

```bash
npm ci
npm run dev
```

Открыть http://localhost:3000.

```bash
npm run lint
npm run build
npm run typecheck
npm run start
```

Проверка браузером (после production build):

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты сами запускают отдельный production-сервер на порту 3100. Проверяют HTTP-статусы, редиректы, метаданные и OG-изображения, ссылки, 404, отсутствие горизонтального скролла на 320/390/768/1440 px, WCAG A/AA через axe на мобильной и десктопной ширине, переход с клавиатуры и ошибки консоли. Для Кружка также проверяются выбор ОС, мышь/касания/клавиатура, согласие на камеру, отказ, отмена и остановка потока при уходе со страницы. В тестах используются искусственная камера и локальный canvas, реальная камера не включается. Для проверки устройств выбран полный Chromium в [новом headless-режиме](https://playwright.dev/docs/browsers#chromium-new-headless-mode), одинаково локально и в CI.

Можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` для существующего Chromium. `TEST_BASE_URL=https://... npm run test:e2e` запускает проверки на внешнем сервере; проверка Host-редиректа рассчитана на локальный сервер и на чужом хостинге может блокироваться платформой.

## Обновление контента

- Тексты: `src/app/page.tsx`, `src/app/kruzhok/page.tsx`, `src/app/bible/page.tsx`.
- Адреса, метаданные и список скачиваний: `src/content/site.ts`.
- Цвета, сетка, адаптивность: `src/app/globals.css`; страница Кружка — `src/app/kruzhok/kruzhok.css`.
- Общая навигация: `src/components/header.tsx`, `footer.tsx`.
- Медиа: `public/`. Для скриншотов используйте `next/image`, размеры и содержательный alt. Короткий ролик Кружка — muted/playsInline/loop с постером и управлением паузой. При prefers-reduced-motion по умолчанию показан статичный кадр.
- Команда `npm run assets` пересоздаёт типографические PNG и favicon через Sharp (на macOS с Arial). Готовые изображения уже включены в Git; серверу этот шаг не нужен.
- Индивидуальные изображения для социальных сетей: `public/og/*.png`, 1200×630. При изменении позиционирования обновите изображение и метаданные вместе.

Обложки — самостоятельная типографическая графика. Они не изображают интерфейсы. На странице Кружка используется предоставленное автором видео; это браузерный пример, а не запись интерфейса настольного приложения. Источники: см. [источники контента](docs/CONTENT_SOURCES.md).

## Скачивание Кружка

Репозиторий `leninblok/floating-camera` открыт владельцем. Основная кнопка выбирает Mac или Windows по ОС браузера. Для Mac используется один универсальный DMG с arm64 и x86_64; для Windows — EXE x64. Под основной кнопкой — прямая текстовая ссылка на другую ОС. Для мобильных и неизвестных ОС основной вариант — Mac, второй — Windows. Вход в GitHub не нужен.

Демо использует оригинальные `renderer.js` и CSS из `index.html` приложения v1.1.0. Тридцать функций расчёта геометрии и анимаций извлечены из `main.js` без изменения тел функций. Их исходные SHA-256, перечень и MIT-лицензия находятся в `public/kruzhok/runtime/`.

Параметры расположены на странице под скачиванием: выбор камеры, круг / прямоугольник, пропорции 1:1 / 4:5 / 9:16 для прямоугольника, соответствующий форме набор размеров, контур, тень, отражение и фокус. Начальные настройки совпадают с новым запуском приложения: большой прямоугольник 9:16, тень включена, контур и отражение выключены. Изменения сохраняются в localStorage этого браузера.

Загрузка — настоящая тёмная оболочка до первого кадра и появление видео за 100 мс. Взяты native-пороги перемещения, объединение событий на один кадр, упругость на границе, возврат за 160 мс и смена геометрии за 180 мс. Двойной клик переключает фокус, блокирует перемещение и возвращает прежние границы при выключении.

Размеры используют `screen.availWidth` / `availHeight` текущего дисплея, исходные поля и 44-пиксельный запас под тень. Камера не уменьшается ради вёрстки: при масштабе браузера 100% сохраняются исходные CSS/DIP-размеры. Позиция ограничена страницей; сайт не управляет окнами ОС, несколькими мониторами и режимом поверх других приложений. На macOS системную тень заменяет CSS-тень из самого приложения; разрешение камеры выдаёт браузер. На компьютере демо остаётся видимым при прокрутке к параметрам, на телефоне показано отдельной областью перед ними.

`browser-preload.js` заменяет Electron IPC и нативное окно, предоставляет видео Леонида как дополнительный локальный источник камеры. Авторский ролик передаётся renderer как Canvas MediaStream без записи и отправки. Физическая камера запрашивается автоматически; до ответа и при отказе остаётся ролик. Микрофон запрещён. Потоки и отрисовка завершаются при уходе со страницы и скрытии вкладки. Политика camera=(self) нужна и при переходе через Next.js; встраивание разрешено только своему origin и только для runtime.

Для обновления из исходного приложения:

```bash
node scripts/sync-kruzhok-runtime.mjs /path/to/floating-camera
node scripts/generate-kruzhok-reference.mjs /path/to/floating-camera
```

Второй скрипт выполняет оригинальный `main.js` в его собственном тестовом окружении и формирует независимый эталон для 42 сочетаний геометрии и последовательности кадров с задержками. Тесты проверяют этот эталон, неизменность renderer/CSS, все открытые параметры, фокус, движение, источники, жизненный цикл камеры, адаптивность и доступность.

`public/kruzhok/intro.mp4`: 303 154 байта, 8 секунд, 640×640, 24 fps, H.264/yuv420p, без аудио, faststart. Постер — JPEG 35 415 байт. Взяты секунды 9–17 из присланного автором `видео.mov`, центральный квадрат 1080×1080; исходник сохранён локально и исключён из Git. Метаданные местоположения не перенесены.

Ссылки, размеры и версия заданы в `src/content/site.ts`. Используются URL конкретного релиза: имена файлов содержат номер версии, поэтому `latest/download` с придуманным стабильным именем не используется.

При обновлении:

1. Опубликовать реальные установщики и SHA256SUMS в новом GitHub Release.
2. Проверить анонимный доступ, соответствие ОС/архитектуры, контрольные суммы и установку на целевых системах.
3. Обновить `kruzhokRelease` и `kruzhokDownloads`, размеры, инструкции и тест ожидаемых URL.
4. Повторить lint, build и браузерные проверки; push в main запустит Vercel.

Универсальная сборка проверяет все Mach-O компоненты на обе архитектуры; команды и ручной release workflow находятся в репозитории приложения. Текущий релиз неподписанный. Инструкции установки и предупреждения macOS/Windows, ссылка на Apple и SHA-256 доступны в GitHub Release. По просьбе владельца на самой странице оставлены только прямые скачивания; версия, бесплатность, GitHub и установка скрыты из интерфейса. Проверка ссылки не означает подтверждение безопасности или ручной проверки приложения на всех ОС.

Установщики хранятся в GitHub Releases, а не в репозитории сайта. Токены и сервер-посредник для скачивания не нужны.

## GitHub, Vercel и домен

Фактический итог публикации и блокеры — в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

Для новой публикации из авторизованной сессии:

```bash
gh auth status
gh api user --jq .login
# Только если репозитория ещё нет:
gh repo create leninblok/leninblock-site --public --source=. --remote=origin --push
npx vercel login
```

В Vercel: **Add New → Project → Import Git Repository → leninblok/leninblock-site**. Перед созданием убедиться, что существующий проект с доменом не занят другим сайтом. Framework: Next.js, Root Directory: `./`, Build: `npm run build`, Node.js: 24.x, Production Branch: `main`. Git-интеграция создаёт production из main и preview из PR. Базовой версии переменные окружения не нужны.

После успешного деплоя: **Project → Settings → Domains → Add Domain** для `leninblock.ru` и `www.leninblock.ru`. Основной адрес — без www, www — redirect. Vercel покажет записи именно этого проекта. У регистратора в разделе DNS внесите эти значения, не меняя NS, MX и почтовые TXT. Не используйте произвольный IP из старых инструкций. Дождитесь статуса Valid Configuration и сертификата, проверьте HTTPS и все маршруты.

Справочники: [DNS Vercel](https://vercel.com/docs/domains/set-up-custom-domain), [Next.js redirects](https://nextjs.org/docs/app/guides/redirecting), [метаданные](https://nextjs.org/docs/app/getting-started/metadata-and-og-images), [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases).

## Новый продукт или кейс

Создайте `src/app/<slug>/page.tsx`, задайте индивидуальные title/description/canonical через `pageMetadata`, добавьте PNG social-preview, карточку на главную и URL в sitemap. Добавляйте в навигацию только страницы с готовым содержимым. Для EASM нужны разрешённые материалы и точное описание: проект не был внедрён, его нельзя представлять как запущенную функцию.

Не переносите сюда исходники «Кружка» и игры. Контакты и частные рабочие материалы публикуйте только после разрешения владельца.
